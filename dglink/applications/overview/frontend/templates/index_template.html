DGLink: Automated knowledge graph construction from biomedical data repositories

While portals supporting user-submitted biomedical data hold substantial scientific value, the re-use of this data at scale is limited by a lack of standardization and annotation. DGLink addresses this gap by automatically assembling portal content into a knowledge graph linking data within a portal and mapping it to external knowledge. This knowledge graph creates a shared interoperability layer that enables knowledge-driven data interpretation and cross-portal discovery. Crucially, the DGLink system not only aggregates existing metadata for projects but also automatically parses and annotates experimental data files directly, greatly increasing annotation depth. For more information on the system please feel free to read the abstract of our talk recently presented at ISMB 2026 or take a look at our GitHub repository.

This page provides access to a DGLink-constructed knowledge graph combining content from multiple National Cancer Institute Cancer Research Data Commons (NCI-CRDC) data portals, namely:

  • The NCI General Commons (GC).
  • The NCI Genomic Data Commons (GDC).
  • The NCI Proteomic Data Commons (PDC).

Additionally, we provide summary statistics for the merged NCI-CRDC knowledge graph and example applications including a structured semantic interface. Finally, we explore how DGLink can integrate into an agentic workflow via an MCP-based knowledge-graph server, providing both example MCP queries and benchmarking MCP performance.

Interoperability

Inside the merge

Every node and edge records the portal(s) it came from. When DGLink recognizes that an entity seen in different portals is the same real-world thing, it collapses them into one node whose portal list keeps every origin. Those shared nodes are the bridges that make cross-portal questions answerable.

Application

Ask the CRDC knowledge graph questions directly

The DGLink Model Context Protocol (MCP) server lets you put a question to the merged CRDC knowledge graph in plain English. It gives LLM agents direct access to the graph, so a single question can reason across the GDC, GC, and PDC — with no Cypher to write.

  • MCP integration: direct, tool-based access to Neo4j via the mcp-neo4j-cypher server.
  • Model-agnostic: works with any MCP-capable client (Claude Desktop, Cursor, or a custom agent).
  • Cross-portal reasoning: a single question can span GDC, GC, and PDC data.

Connect

Add the MCP server to your own LLM

DGLink serves the merged graph over a streamable-HTTP MCP endpoint, so any MCP-capable client — Claude Desktop, Claude Code, Cursor, or a custom agent — can connect with just a URL. No authentication is required, and there is nothing to install locally: no uv, no Python, no Neo4j driver.

For example, to add it to Claude Desktop, merge the following into claude_desktop_config.json:

{
  "mcpServers": {
    "dglink-crdc": {
      "url": "{{ mcp_http_url }}"
    }
  }
}

Or from the command line with Claude Code:

claude mcp add --transport http dglink-crdc {{ mcp_http_url }}

Your client then gets tools to inspect the graph schema and run read Cypher against it. The endpoint is read-only, so queries can explore the graph but never modify it. Older clients without native remote-MCP support can bridge to the same URL with npx mcp-remote {{ mcp_http_url }}.

Benchmark

Does the knowledge graph help? Raw API vs. knowledge graph agent

One immediate follow-up question to this type of approach might be, “Is the knowledge graph actually necessary, or could a state-of-the-art LLM get the same result if just given access to a portal’s API?” We can test exactly this by giving the same agent the same question twice: once with only API access, and once with access to the knowledge graph. Everything else is held constant — same model, system prompt, and turn budget — so the only variable is the MCP toolset.

All trials were run using Claude Sonnet 5 headless via claude -p, with the built-in file and shell tools disabled so an agent’s only capability is its own MCP server.

  • Raw-API agent: Agent was given access to each portal's GraphQL client as well as tools for previewing and downloading portal data files.
  • Knowledge graph (KG) agent (DGLink): Agent was given direct MCP access to the merged CRDC KG.

Both agents can reach the same files — the comparison is pre-indexed graph vs. search-at-query-time, not “can read files” vs. “can’t”.

Query 1 · cross-portal

Is TP53 present in all three CRDC portals?

“Is the gene TP53 present in all three CRDC portals in the ingested data — a GDC case, a GC (General Commons) study, and a PDC proteomic study? Name the specific study/case in each portal.”

MetricRaw-API agentDGLink KG agent
Agent turns267
Output tokens11,7391,573
Wall time169.6 s31.1 s
Cost (USD)$0.63$0.17

Comparison. The KG agent answered in roughly a quarter of the turns, an eighth of the output tokens, and a third of the cost — and reached a more complete answer. From a single merged gene node it confirmed TP53 in all three portals, whereas the raw-API agent confirmed GDC and PDC but could not verify the GC link from the metadata API alone.

Gene panel · scored vs. independent gold

Which of a 20-gene panel appear in caNanoLab data files?

“For each gene in this 20-gene panel, determine whether it appears in any data file of the caNanoLab study (NCI General Commons, phs_accession 10.17917).”

Unlike the open-ended queries above, this task is scored automatically against an independent gold standard (14 of the 20 panel genes are truly present). Both agents have perfect precision (i.e. no false positives); however, they differ sharply in recall.

Comparison. Both agents are perfectly precise, but the KG agent recovers 12 of the 14 gold-positive genes (F1 0.92) versus only 4 for the raw-API agent (F1 0.44). Because file-content gene mentions are pre-indexed on the graph, the KG agent reads them off the study node directly; the raw-API agent, limited to filename/metadata text search, cannot see genes buried inside the study’s data tables — at a third the recall, and for 7× the cost.
